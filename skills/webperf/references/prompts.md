# Web performance recipes

31 recipes from [`mrconcol/vibecode-speed-prompts`](https://github.com/mrconcol/vibecode-speed-prompts), written by the same author as this repository and included here with their permission.
Each recipe has the same shape: find the place, change it, verify it, or say it does not apply and change nothing. The wording is kept in Russian.

Read only the section you need.

## 1. Покажи серые заглушки при загрузке

```text
Найди экраны и компоненты, которые подгружают данные и пока показывают пустое место или крутилку.
Для каждого сделай серую заглушку по форме будущего содержимого (заголовок, карточка, строка списка).
Убирай заглушку, когда данные пришли; ошибку загрузки показывай отдельно.
Проверь: открой экран с замедленной сетью, вместо пустоты должна быть заглушка.
Если в проекте нет загрузки данных на экранах, скажи об этом и ничего не меняй.
```

## 2. Отдавай картинки WebP и AVIF

```text
Найди все картинки проекта и места, где они подключаются.
Сконвертируй их в WebP и AVIF, оригинал оставь запасным вариантом для старых браузеров.
Подключи через picture/srcset или средствами фреймворка, чтобы браузер брал современный формат.
Проверь: во вкладке Network у картинок тип webp или avif, страница выглядит как раньше.
Если картинок нет, скажи об этом и ничего не меняй.
```

## 3. Не допускай дублирующих запросов к API

```text
Найди в коде все обращения к API и проверь, не вызываются ли одни и те же запросы по несколько раз
(из разных компонентов, при каждом рендере, при повторном открытии экрана).
Объедини их: общий кэш запросов (React Query, SWR или аналог) либо один вызов на верхнем уровне.
Проверь: во вкладке Network одинаковых запросов подряд нет.
Если дублей нет, скажи об этом и ничего не меняй.
```

## 4. Отправляй поиск и автодополнение только тогда, когда человек перестал печатать

```text
Найди поля поиска и автодополнения, которые шлют запрос на каждое нажатие клавиши.
Добавь debounce: запрос уходит, когда человек перестал печатать на короткую паузу; прошлый запрос отменяй.
Паузу вынеси в одну константу.
Проверь: набери слово быстро, в Network должен уйти один запрос, а не по запросу на букву.
Если такого поля нет, скажи об этом и ничего не меняй.
```

## 5. Отдавай результаты API постранично

```text
Найди эндпоинты и запросы, которые возвращают целые списки без ограничений.
Добавь постраничную выдачу: страница (или курсор) и лимит, в ответе признак «есть ещё».
Обнови интерфейс: следующая порция подгружается по кнопке или при прокрутке.
Проверь: запрос списка возвращает одну порцию, следующая приходит по запросу.
Если все списки в проекте короткие и ограничены, скажи об этом и ничего не меняй.
```

## 6. Раздавай статические файлы через CDN

```text
Найди статические файлы проекта (картинки, шрифты, JS, CSS, видео) и определи, откуда они отдаются сейчас.
Предложи и настрой раздачу через CDN: префикс адресов в конфиге сборки или хостинга.
Адрес вынеси в одну настройку, чтобы её можно было переключить обратно.
Проверь: файлы в Network приходят с адреса CDN, страница работает как раньше.
Если статика уже отдаётся через CDN, скажи об этом и ничего не меняй.
```

## 7. Вынеси медленные задачи в фоновую очередь

```text
Найди в запросах пользователя медленные операции: отправка писем, обработка файлов, вызовы ИИ, отчёты, экспорт.
Вынеси их в фоновую очередь, а пользователю сразу отвечай «принято» со статусом задачи.
Добавь повтор при ошибке и способ узнать результат (опрос статуса или уведомление).
Проверь: запрос возвращается сразу, работа заканчивается в фоне, результат виден.
Если медленных операций в запросах нет, скажи об этом и ничего не меняй.
```

## 8. Исправь запросы N+1

```text
Найди места, где для каждого элемента списка выполняется отдельный запрос к базе (запрос внутри цикла, ленивая загрузка связей).
Замени на один запрос с join или предзагрузку связей (include, select_related, with и аналоги).
Включи лог запросов и сравни их количество до и после на одной странице.
Проверь: число запросов не растёт вместе с длиной списка.
Если N+1 нет, скажи об этом и ничего не меняй.
```

## 9. Включай сжатие Brotli или Gzip

```text
Проверь, сжимаются ли текстовые ответы (HTML, JSON, JS, CSS, SVG) на сервере или хостинге.
Включи Brotli и оставь Gzip запасным для клиентов без поддержки br: в конфиге сервера, прокси или фреймворка.
Не сжимай то, что уже сжато (картинки, видео, архивы).
Проверь: в заголовках ответа content-encoding равен br или gzip.
Если сжатие уже включено, скажи об этом и ничего не меняй.
```

## 10. Кэшируй часто запрашиваемые данные в Redis

```text
Найди данные, которые часто читаются и редко меняются: справочники, настройки, результаты тяжёлых выборок.
Добавь для них кэш в Redis с понятным ключом и временем жизни, при изменении данных сбрасывай ключ.
Если Redis в проекте нет, предложи вариант и дождись моего ок, прежде чем что-то ставить.
Проверь: повторный запрос тех же данных не доходит до базы, после изменения ответ свежий.
Если подходящих данных нет, скажи об этом и ничего не меняй.
```

## 11. Удали неиспользуемые зависимости

```text
Прогони проверку неиспользуемых зависимостей (depcheck, knip или аналог для моего стека).
Составь список пакетов, которые нигде не импортируются, и покажи его мне.
После моего ок удали их из package.json (или аналога для моего стека) и обнови lock-файл.
Проверь: проект собирается, тесты проходят, приложение запускается.
Если лишних пакетов нет, скажи об этом и ничего не меняй.
```

## 12. Поставь таймауты на внешние API

```text
Найди все вызовы внешних сервисов (платежи, почта, ИИ, сторонние API) и посмотри, задан ли у них таймаут.
Добавь таймаут на каждый вызов, а для безопасных запросов ограниченное число повторов.
Сделай понятную обработку: что видит пользователь, если внешний сервис не ответил.
Проверь: подставь заведомо медленный адрес, запрос должен оборваться по таймауту.
Если внешних вызовов нет или таймауты уже стоят, скажи об этом и ничего не меняй.
```

## 13. Выводи ответы ИИ потоком, токен за токеном

```text
Найди места, где приложение вызывает модель ИИ и ждёт ответ целиком.
Переведи вызов на потоковый режим (stream) и выводи текст в интерфейсе по мере поступления.
Учти отмену запроса и ошибку посреди потока.
Проверь: текст появляется по частям сразу после отправки, а не одним куском в конце.
Если ИИ в проекте не используется, скажи об этом и ничего не меняй.
```

## 14. Обновляй интерфейс, не дожидаясь ответа сервера

```text
Найди действия, после которых интерфейс ждёт ответ сервера: лайк, добавление, переключатель, отметка выполненного.
Сделай оптимистичное обновление: интерфейс меняется сразу, а при ошибке сервера откатывается и показывает сообщение.
Применяй только там, где откат безопасен; платежи и необратимые действия не трогай.
Проверь: клик меняет экран мгновенно, при имитации ошибки состояние возвращается.
Если подходящих действий нет, скажи об этом и ничего не меняй.
```

## 15. Подгружай картинки за пределами экрана только при прокрутке

```text
Найди картинки, которые расположены ниже первого экрана.
Включи для них ленивую загрузку (loading="lazy" или средства фреймворка), для картинок первого экрана оставь обычную.
Задай размеры картинок, чтобы страница не прыгала при подгрузке.
Проверь: при открытии страницы нижние картинки не грузятся, они появляются при прокрутке.
Если все картинки на первом экране, скажи об этом и ничего не меняй.
```

## 16. Запускай независимые запросы параллельно

```text
Найди места, где несколько запросов (к API или к базе) идут друг за другом, хотя не зависят друг от друга.
Запусти их параллельно (Promise.all, asyncio.gather и аналоги), сохранив обработку ошибок.
Зависимые запросы оставь последовательными.
Проверь: в Network или в логах независимые запросы стартуют одновременно, результат тот же.
Если таких мест нет, скажи об этом и ничего не меняй.
```

## 17. Добавь в базу индексы под частые запросы

```text
Найди самые частые и медленные запросы к базе: условия WHERE, JOIN, ORDER BY.
Для каждого посмотри план выполнения (EXPLAIN) и покажи, где идёт полный перебор таблицы.
Предложи индексы под эти запросы и напиши миграцию; применяй после моего ок.
Проверь: план запроса использует индекс, результат запроса не изменился.
Если нужные индексы уже есть, скажи об этом и ничего не меняй.
```

## 18. Отслеживай медленные запросы бэкенда через OpenTelemetry

```text
Подключи OpenTelemetry к бэкенду: трассировка входящих запросов, вызовов базы и внешних API.
Выбери экспорт, который подходит проекту, настройки вынеси в переменные окружения.
Не пиши в трассы персональные данные и секреты.
Проверь: в трассе видно время каждого запроса и вызова базы, медленные выделяются.
Если трассировка уже настроена, скажи об этом и ничего не меняй.
```

## 19. Ставь серверы рядом с базой данных

```text
Определи по конфигам, в каких регионах стоят сервер приложения и база данных.
Если они в разных регионах, покажи это и предложи вариант переноса; сам ничего не переноси без моего ок.
Опиши, как измерить задержку между приложением и базой до и после переноса.
Проверь: в отчёте указаны регионы приложения и базы и способ измерить задержку между ними.
Если они уже в одном регионе, скажи об этом и ничего не меняй.
```

## 20. Рендери страницы на сервере или при сборке

```text
Определи, какие страницы целиком рисуются в браузере, хотя их содержимое известно заранее или одинаково для всех.
Переведи их на серверный рендеринг или генерацию при сборке средствами моего фреймворка.
Страницы с личными данными оставь как есть.
Проверь: в исходном HTML страницы уже есть текст и контент, а не пустой корневой элемент.
Если фреймворк так не умеет или страницы уже так рендерятся, скажи об этом и ничего не меняй.
```

## 21. Подключай сторонние скрипты после загрузки страницы

```text
Найди сторонние скрипты: аналитика, чат поддержки, пиксели, виджеты.
Подключи их с defer или async либо загружай после готовности страницы или после первого действия пользователя.
Не ломай то, что нужно сразу (например, согласие на cookie).
Проверь: страница показывается и работает без ожидания этих скриптов, они подгружаются позже.
Если сторонних скриптов нет, скажи об этом и ничего не меняй.
```

## 22. Дели JavaScript по страницам

```text
Проанализируй сборку: какие страницы и тяжёлые библиотеки попадают в общий бандл.
Включи разделение кода: динамический import для страниц и тяжёлых компонентов (редактор, графики, карты).
Покажи мне отчёт сборки до и после.
Проверь: у каждой страницы свой файл, приложение работает как раньше.
Если код уже разделён по страницам, скажи об этом и ничего не меняй.
```

## 23. Виртуализируй длинные списки

```text
Найди списки и таблицы, которые выводят сразу все элементы.
Подключи виртуализацию (react-window, TanStack Virtual или аналог): в DOM остаются только видимые строки.
Сохрани прокрутку, поиск и фокус с клавиатуры.
Проверь: при длинном списке в DOM лишь видимые строки, прокрутка плавная.
Если длинных списков нет, скажи об этом и ничего не меняй.
```

## 24. Выбирай из базы только нужные колонки

```text
Найди запросы вида SELECT * и загрузку целых объектов, когда нужны одно-два поля.
Замени на выбор только нужных колонок; тяжёлые поля (тексты, JSON, файлы) тяни только там, где они нужны.
Проверь: данные на экране прежние, в логе запросов перечислены конкретные колонки.
Если везде уже выбираются нужные колонки, скажи об этом и ничего не меняй.
```

## 25. Используй пул подключений к базе

```text
Проверь, как приложение подключается к базе: новое соединение на каждый запрос или общий пул.
Настрой пул с разумным максимумом и таймаутом ожидания; для serverless и малых лимитов базы используй пулер.
Возвращай соединения в пул после запроса.
Проверь: при повторных запросах число открытых соединений остаётся в пределах пула.
Если пул уже настроен, скажи об этом и ничего не меняй.
```

## 26. Убери лишние перерисовки

```text
Найди компоненты, которые перерисовываются без изменения данных: новые объекты и функции в пропсах, состояние слишком высоко по дереву, контекст, который меняется целиком.
Исправь точечно: мемоизация, вынос состояния ближе к месту использования, разделение контекста.
Не добавляй мемоизацию везде подряд, только там, где перерисовка подтверждена.
Проверь через React DevTools Profiler (или аналог): лишних перерисовок нет.
Если проблем нет или фреймворк не про перерисовки, скажи об этом и ничего не меняй.
```

## 27. Включи кэширование статики в браузере

```text
Проверь заголовки Cache-Control у статических файлов: JS, CSS, шрифты, картинки.
Файлам с хешем в имени поставь долгий срок кэша с immutable, а HTML оставь с коротким сроком или проверкой.
Убедись, что при новом выпуске имена файлов меняются и пользователи получают свежую версию.
Проверь: при повторной загрузке статика берётся из кэша браузера.
Если кэш уже настроен правильно, скажи об этом и ничего не меняй.
```

## 28. Распредели нагрузку между несколькими копиями приложения

```text
Проверь, можно ли запустить несколько копий приложения: нет ли состояния в памяти процесса (сессии, загруженные файлы, локальный кэш).
Если такое состояние есть, предложи, куда его вынести (база, Redis, объектное хранилище).
Опиши настройку балансировщика и проверок живости; инфраструктуру сам не меняй без моего ок.
Проверь: две копии обслуживают один и тот же сеанс пользователя без потерь.
Если приложение уже работает в нескольких копиях, скажи об этом и ничего не меняй.
```

## 29. Храни шрифты у себя и ограничь число начертаний

```text
Найди подключённые шрифты и узнай, откуда они грузятся (внешний сервис или свой сервер).
Скачай нужные файлы и раздавай их со своего домена в формате woff2; оставь только используемые начертания и языки.
Добавь font-display, чтобы текст был виден во время загрузки шрифта.
Проверь: в Network шрифты приходят с моего домена, лишних начертаний нет.
Если шрифты системные или уже раздаются с моего домена, скажи об этом и ничего не меняй.
```

## 30. Следи за скоростью у реальных пользователей через мониторинг

```text
Подключи мониторинг реальных пользователей: метрики Core Web Vitals (LCP, INP, CLS) и ошибки из браузера.
Выбери инструмент, который подходит проекту (web-vitals и любой приёмник данных), ключи вынеси в переменные окружения.
Не отправляй персональные данные.
Проверь: после захода на сайт метрики приходят в панель мониторинга.
Если мониторинг уже подключён, скажи об этом и ничего не меняй.
```

## 31. Тестируй на слабых телефонах и медленном интернете

```text
Настрой проверку на слабом устройстве и медленной сети: профиль замедленной сети и процессора в DevTools или Lighthouse.
Прогони главные сценарии (первая загрузка, вход, главный экран, основное действие) и составь отчёт: что тормозит и почему.
Добавь команду или скрипт для повторной проверки; правки пока не вноси.
Проверь: в отчёте конкретные страницы и причины, а не общие слова.
Если проверка на слабом устройстве уже настроена, скажи об этом и ничего не меняй.
```
